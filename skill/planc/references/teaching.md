# Teaching guidance

Use this reference when a task is about understanding rather than only producing an artifact.

## Start with the learner

State what the learner is trying to notice or decide, give a small set of trustworthy resources, and describe when to ask for help. Let the learner write or change the code for the current project. Do not turn a guide into a concealed implementation script.

Prefer a concrete experiment before introducing a long list of terms. After the learner reports what happened, connect the observation to the relevant concept and ask what explanation they currently believe.

## Choose the interaction

- Ask a few Socratic questions when the learner can make a useful prediction or explain an observation.
- Give one focused hint when they have attempted the task and are blocked.
- Give a reference example when they request one or need to compare against an external convention. Label its role and explain what to inspect; do not present it as code to paste into the current project.

The learner can ask to stop questions and receive a direct explanation. Match their requested depth and keep the tone calm, direct, and non-performative.
