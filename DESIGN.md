# planc interface

The interface adapts the typography and flat, terminal-like structure of the [OpenCode design analysis](https://getdesign.md/opencode.ai/design-md), using the [Catppuccin Mocha palette](https://github.com/catppuccin/palette). It is a working task viewer, not a marketing page.

- Use monospace typography throughout, with a CJK monospace fallback. Berkeley Mono is commercial; use a system stack starting with JetBrains Mono instead of distributing it.
- Keep the three working areas: topic/task index, dependency graph, and inspector. Separate them with 1px rules. Use square section boundaries, at most 4px corners on controls, and no shadows or gradients.
- Use Mocha base (`#1e1e2e`), mantle (`#181825`), and crust (`#11111b`) for background layers. Text is `#cdd6f4`; secondary text is `#a6adc8`; borders use surface0 (`#313244`) and surface1 (`#45475a`).
- State colors: completed green (`#a6e3a1`), in progress yellow (`#f9e2af`), ready blue (`#89b4fa`), blocked overlay1 (`#7f849c`). Selection, brand accents, and related edges use mauve (`#cba6f7`); errors use red (`#f38ba8`).
- Keep label sizes fixed, spacing in 4px increments, and letter spacing at zero. Use Lucide icons for controls, plus explicit status labels and tooltips.
- The real dependency graph is the main visual. Lay out all topic members before filtering and retain selection and viewport on updates. Keep desktop and mobile flows equally usable.
- Snap the Dagre layout to a 24px grid. Taking inspiration from [Better Questing's rectilinear connections](https://github.com/Funwayguy/BetterQuesting/blob/1.12/src/main/java/betterquesting/api2/client/gui/resources/lines/LineTaxiCab.java), route connections between tasks horizontally, vertically, or at 45 degrees. PathFinding.js routes around all nodes, including hidden ones. Self-associations use Cytoscape's arrowed loop. Cache the routes with the layout; viewing and filtering do not move nodes.
- Every connection has one arrowhead, pointing from `from` to `to`. Prerequisites point from the prerequisite to the dependent task; implicit prerequisites use dashed arrows, and ordinary associations use dashed mauve arrows. Never use double-headed arrows. Associations still have no effect on readiness. The canvas remains a read-only view with freely pannable and zoomable navigation.

The maintained palette lives in `web/style.css`; Cytoscape reads the same CSS variables. Build outputs are generated by `npm run build`.
